# YYYY-MM-DD — Change title

Status: proposed / implemented / tested / deployed / rolled back

## Request and purpose

Who requested the change; concrete problem and expected user behavior.

## Scope and source

Component versions, branch/commit, changed files, source of evidence.
Secrets and personal data omitted.

## Implementation and decisions

What changed and why; alternatives considered when relevant; schema/config effects.

## Validation

Commands/tests, expected versus actual outcomes, date/environment.
Separate syntax, mock, integration, visual and user-reported results.
State untested behavior and material risks.

## Deployment

Authorization/context, UTC time, prior/new versions, checkpoint location outside
Git, migrations, runtime reloads, queue state and post-change evidence.
Leave explicitly not deployed when appropriate.

## Rollback and follow-up

Reversible source steps, data compatibility, external side effects, unresolved work.
